以上以 CSS 像素计。每组冰层上缘距离人物包围框顶部至少为高度的 44.1%，下移后仍能看到脚边的透光效果。 [四端测量数据](复核量测.json)

- 治疗与护盾 ADD 发光强度乘以 0.65。支援光效的爆发核心在人物后方，常驻盾壳仍在角色前方。独立离线同帧对照中，三个受盾人脸采样区域内的近白像素（R、G、B 均至少 248）原为 189、170、148 个，六个治疗人脸区域合计原有 227 个，改后这些区域均为 0。冰层压到胸腹以下，融化碎片保持低位。 [人脸像素对照](face-pixel-sample.json) · [光效参数及离线资源](vfx-validation.json)
- 浮字使用 120% 的原字号，抽检放大后的盾字和治疗字与目标血条之间仍有可见空隙。总伤以视窗内 16:9 舞台为基准向右偏移，底距约 20.4%，保留羽化光晕；治疗及护盾总额仍居中。
- 镜头测试检查 Pixi 实际投影后的在场单位完整矩形。专项将最右敌人设为后排最低血量，莉莉丝据真实战斗规则命中该单位，截图包含尾击踢震。另以更宽的薇尔贴图占据最右阵位在三个视口独立复测。 [镜头压力样本](polish-camera.json)
- 四组专项均无页面、控制台、HTTP 或资源错误。双击入口的特效解包 SHA-256 与原文件一致，且全程零外部 HTTP 请求。全量 115 张原 PNG 的 SHA-256 前后一致。 [本轮原图指纹](visual-polish-baseline.json)
- 四组全流程并行回归通过，覆盖菜单入口、实战动作和结算，全部零报错。最终绘制分层使用四组 HUD 专项与同帧人脸像素抽样复核。Node 核心测试 14 项全过。 [桌面全流程](desktop-full-workflow.json) · [高分屏全流程](retina-full-workflow.json) · [横屏全流程](mobile-full-workflow.json) · [离线全流程](file-full-workflow.json)

## 复跑

需 Node、Playwright 和 Chrome。在项目根目录运行，按本机设置 `NODE_PATH` 与 Chrome 路径。

```powershell
node --test tests/core.cjs
$chrome = "$env:ProgramFiles\Google\Chrome\Application\chrome.exe"
node tests/browser.cjs --hud-only --case desktop,retina,mobile,file --chrome $chrome --out "$env:TEMP\sky-visual-polish"
node tests/browser.cjs --case desktop,retina,mobile,file --chrome $chrome
```
