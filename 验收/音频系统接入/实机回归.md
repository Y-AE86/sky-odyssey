# 双轨 BGM 与音效系统实机验收

在 `dev/sky-odyssey` 使用 Chrome 测试本地 HTTP 与直接打开本机 `index.html`。两组均从游戏页面触发音频，包含有声必杀自然结束、点击跳过、静音必杀、战后结算及重载存档。HTTP 使用真实鼠标点击解锁，双击入口使用实际键盘事件解锁。Chrome 以系统输出静音启动，以下播放结论来自浏览器解码字节、播放位置、原生音量值和 Web Audio 节点。

| 指标 | HTTP | file:// |
| --- | ---: | ---: |
| 首次确认主城解码字节 | 11,284 | 11,911 |
| 首次确认战斗解码字节 | 11,284 | 17,554 |
| 进战 / 返回交叉淡入 | 630 / 650 ms | 584 / 651 ms |
| 首次进战最大单次原生音量变化 | 0.0131 | 0.0340 |
| 有声必杀压低至原音量 | 22% | 22% |
| 自然结束 / 手动跳过恢复 | 394 / 395 ms | 395 / 395 ms |
| 受测流程实际振荡器触发 | 138 | 136 |
| 控制台、页面、HTTP、资源错误 | 0 | 0 |

两首音乐实际进入播放、推进时间且设为循环。离线游戏没有外部 HTTP 请求，也没有用 `fetch` 读取 MP3。进战首批画面资源解码造成的帧间隔会经过音量步幅限制，首进战仍保留完整淡变。实测有声必杀淡出 200–254 ms。主城看板实测一直以静音播放。无头 Chrome 的冻结/激活命令未产生可见性事件，测试通过注入隐藏状态并派发 `visibilitychange` 对真实音轨验证了暂停、时间不增长和恢复自原位置。

## 实测证据

- 本地 HTTP 与双击入口的直接媒体检查与存档回读。[HTTP 报告](http-report.json) · [双击报告](file-report.json) · [HTTP 音量与音效事件](http-timeline.json) · [双击音量与音效事件](file-timeline.json)
- 游戏实测触发按钮、切页、返回、收星匣、升级、十连，以及近战、施法、受击、暴击、盾、治疗、必杀起手和战败提示。独立 Chrome 夹具逐个跑了全部 15 类合成，通过压缩器观测到真实输出。另用临时 WAV 验证真音效优先、变化不超过 ±5% 的播放速率、损坏素材回退合成和静音停止样本。HTTP 样本接入同一压缩器，`file://` 使用原生保守音量且限制同时四声部。[合成及真素材报告](sky-audio-effects-probe.json)
- 改动后两种入口的既有游戏完整回归。[HTTP 全流程](http-full-workflow.json) · [双击全流程](file-full-workflow.json)
- 主城与战斗均可一键全局静音，设置页可独立切换背景音乐和音效并调音量，含 PeriTune 署名。测试覆盖滑块键盘操作、全局开关仅恢复已启用类别、旧档默认设置和键值持久化。手机核验为 844×390、DPR 3、左右 44/35 像素安全区的 Chrome 模拟。[桌面设置](http-settings.png) · [战斗顶栏](file-battle-control.png) · [横屏设置](settings-audio-mobile.png) · [横屏测量](settings-audio-mobile.json)
- 两首 MP3 与 115 张原 PNG 的 SHA-256 全部相同。临时清单夹具覆盖 MP3、OGG 和 WAV、大小写扩展名及带空格文件名，重复运行输出一致。[原素材指纹](audio-baseline.json) · [清单夹具结果](audio-registry-review.json)

28 个 JS/CJS、5 份 CSS、3 个 PowerShell 和 4 个 Python 文件通过语法检查，Node 核心测试 14 项全过。

## 复跑

在项目根目录运行。Chrome 路径和 Playwright 的 `NODE_PATH` 按本机实际位置设置。

```powershell
node _tools/sync-audio.cjs
node --test tests/core.cjs
$chrome = "$env:ProgramFiles\Google\Chrome\Application\chrome.exe"
node tests/audio-browser.cjs --chrome $chrome --case http,file
```
